## Pass 1 findings

1. A real GUI function review succeeded, but Apply failed before source writes
   with Windows `EPERM: operation not permitted, fsync`. The source journal
   reopened its own temporary file read-only; Windows flushing needs a writable
   handle. Changed to `r+`, preserving write-ahead durability. Existing journal
   recovery tests pass on Windows after the fix.
2. The SQL agent's browser found the fixed Prisma contract-path guard compared
   Windows backslashes with a forward-slash constant, blocking Database. The
   guard now normalizes separators. SQL/recovery views also remain available
   when Prisma source loading fails.
3. Independent release review found a configured output such as `src` could
   relocate authored files as a previous-output backup. The release owner is
   hardening path authority before acceptance.
